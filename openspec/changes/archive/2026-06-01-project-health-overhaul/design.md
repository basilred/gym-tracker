## Context

Gym Tracker — React 19 SPA на Vite 7. Данные хранятся в localStorage, деплой на GitHub Pages. Кодовая база ~600 строк JS/JSX, без тестов и типизации. Аудит выявил 38 проблем: критические баги (UTC-дата, деление на ноль), нулевое a11y-покрытие, неполный PWA, устаревшие зависимости. Проект компактный — лучшее время для фундаментальных улучшений.

## Goals / Non-Goals

**Goals:**
- Достичь >80% test coverage на хуках и ключевых компонентах
- Полная миграция на TypeScript strict mode
- Соответствие WCAG 2.1 AA (клавиатура, скринридеры, семантика)
- Устойчивость к runtime-ошибкам через Error Boundary
- Полноценная PWA-конфигурация
- Тёмная тема и адаптивная вёрстка

**Non-Goals:**
- Backend / серверная часть
- Авторизация / мульти-пользователь
- Миграция с localStorage на другую БД
- Интернационализация (i18n)
- Серверный рендеринг (SSR)

## Decisions

### 1. Vitest + React Testing Library (а не Jest + Enzyme)

**Почему**: Vitest — нативный ESM, zero-config с Vite, быстрее Jest в 2-5x. React Testing Library — стандарт индустрии, тесты приближены к пользовательскому поведению. Enzyme deprecated с React 18+.

**Альтернатива (Jest)**: требовал бы babel/jest.config, медленнее, хуже ESM-поддержка.

### 2. TypeScript strict mode с нуля

**Почему**: Включаем сразу `strict: true` (noImplicitAny, strictNullChecks, etc.). На маленькой кодовой базе это не больно, а долгосрочно спасает от целого класса багов.

**Стратегия миграции**: hooks first (useSubscriptions — чистая логика без JSX), затем компоненты снизу вверх (листья → страницы → App). Каждый файл конвертируется и сразу проверяется `tsc --noEmit`.

### 3. Error Boundary как классовый компонент

**Почему**: React 19 не поддерживает функциональные Error Boundaries (экспериментальный `use` API нестабилен). Классовый компонент — единственный стабильный способ.

**Архитектура**: `ErrorBoundary` оборачивает `<Routes>` в `App.jsx`. При ошибке показывает fallback с кнопкой «Попробовать снова» (перемонтирует дерево через `key`).

### 4. Accessibility: нативные API вместо библиотек

**Почему**: Проект маленький, тащить react-aria или radix-ui — избыточно. Добавляем атрибуты руками, следуя WAI-ARIA Authoring Practices.

**Клавиатурный свайп**: на `Escape` — возврат, на `Delete`/`Backspace` — удаление. Кнопка удаления видна при `:focus-visible` без необходимости свайпа.

### 5. Валидация формы — нативная, не библиотека

**Почему**: Одна форма с тремя полями. Formik или react-hook-form здесь — оверкилл. Используем Constraint Validation API (HTML5 `required`, `minlength`, `maxlength` + кастомная валидация).

### 6. Тёмная тема через CSS custom properties

**Почему**: Токены уже определены в `:root`. Добавляем `@media (prefers-color-scheme: dark)` с переопределением значений — без JS, без переключения, без классов на body. Автоматически следует системной теме.

### 7. Фикс UTC-даты через ручное форматирование локального времени

**Почему**: `new Date().toISOString().split("T")[0]` даёт UTC-дату. Для `new Date()` в локальном часовом поясе достаточно собрать строку из `getFullYear()`, `getMonth() + 1`, `getDate()` — это прозрачно, не зависит от магической локали и гарантированно даёт формат `YYYY-MM-DD`, ожидаемый `<input type="date">`.

**Альтернатива (`toLocaleDateString('sv-SE')`)**: работает, но семантически странно — Швеция выбрана только потому, что её локальный формат совпадает с ISO. Ручная сборка намерения понятнее.

### 8. Фикс деления на ноль — guard на уровне компонента

**Почему**: `totalSessions` может быть 0 при создании или повреждённых данных. Добавляем `Math.max(totalSessions, 1)` при расчёте прогресса и блокируем кнопку «Отметить посещение» при `totalSessions <= 0`.

### 9. Фикс button-in-Link — реструктуризация разметки

**Почему**: Сейчас карточка-ссылка содержит кнопку меню — невалидный HTML. Перестройка: карточка-ссылка для навигации, кнопка меню — отдельный интерактивный элемент вне `<a>`, позиционируется абсолютно поверх карточки.

### 10. PWA: стратегия stale-while-revalidate

**Почему**: Приложение — статический SPA, данные в localStorage. Workbox-стратегия `stale-while-revalidate` для навигации обеспечит мгновенную загрузку из кеша с фоновым обновлением. `cacheFirst` для статических ресурсов.

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| TypeScript strict mode замедлит разработку на первых порах | Кодовая база мала — боль минимальна. Мигрируем за 1-2 сессии |
| Миграция может сломать production | Деплой только через GitHub Pages из `dist/`; тесты и `tsc --noEmit` перед деплоем |
| — | — |
| PWA-кеш может устареть после деплоя | `autoUpdate` + `skipWaiting` в конфиге обеспечат обновление при следующей навигации |
| Тёмная тема — только системная, без ручного переключения | Приемлемо для v1. Ручное переключение — отдельный change |
