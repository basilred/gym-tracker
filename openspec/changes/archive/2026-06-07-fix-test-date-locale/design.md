## Context

Компоненты используют `new Date().toLocaleDateString()` без аргументов для форматирования дат. В jsdom-окружении результат зависит от системной локали машины, на которой запускаются тесты. Это приводит к 8 падающим тестам на `ru-RU` системах.

## Goals / Non-Goals

**Goals:**
- Зафиксировать локаль `en-US` в тестовом окружении для детерминированных тестов дат
- Поправить 8 тестов — заменить регекспы на формат, соответствующий `en-US`

**Non-Goals:**
- Не менять production-код (он должен уважать системную локаль пользователя)
- Не добавлять `i18n` или поддержку множественных локалей
- Не форматировать даты вручную

## Decisions

**Decision:** Мок `Date.prototype.toLocaleDateString` в `src/app/test-setup.ts`

Альтернативы:
- **`LC_ALL` env var** — нестабильно на разных платформах
- **Кастомный матчер** — требует правки каждого теста, не решает проблему глобально
- **Мок через `vi.spyOn` в каждом тесте** — дублирование кода

Мок на уровне test-setup — минимальное изменение, покрывает все тесты разом, легко отменяется если в будущем появится нормальная система интернационализации.

## Risks / Trade-offs

- **Мутация прототипа Date** — если в будущем появится тест, проверяющий `toLocaleDateString` с конкретной локалью, мок придётся размокивать в этом конкретном тесте. Маловероятно для текущего проекта.

- **Не влияет на production** — мок работает только в тестовом окружении (jsdom), не затрагивает production-сборку.
