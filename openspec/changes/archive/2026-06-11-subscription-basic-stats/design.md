## Context

Сейчас на детальной странице подписки показывается прогресс-бар, количество оставшихся занятий и таймлайн визитов. Аналитики нет. Все данные для базовой статистики уже есть в модели Subscription (visits[], startDate, totalSessions) — никаких изменений модели не требуется.

## Goals / Non-Goals

**Goals:**
- Показывать частоту посещений (визитов в неделю)
- Показывать количество дней с последнего визита
- Показывать прогноз даты окончания (если достаточно данных)
- Показывать максимальный перерыв между визитами
- Вся аналитика под таймлайном на странице подписки

**Non-Goals:**
- Графики или визуализации (только текст/цифры)
- Кросс-подписочная аналитика (сводка по всем)
- Изменение модели данных Subscription
- Новая страница /stats
- Календарь или тепловая карта

## Decisions

### 1. Архитектура: shared/lib + виджет

Новая чистая функция `calcSubscriptionStats` в `shared/lib` — без зависимостей от React, легко тестируется. Новый виджет `SubscriptionStats` в `widgets/subscription-stats/` — принимает данные и рендерит блок.

```
                    ┌───────────────────────────┐
                    │  SubscriptionDetail        │
                    └─────┬─────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          │               │               │
          ▼               ▼               ▼
   VisitTimeline   MarkVisitButton  SubscriptionStats
                                       │
                                       ▼
                               calcSubscriptionStats
                               (shared/lib, чистая функция)
```

### 2. Формулы расчётов

**Frequency**: `visits.length / max(weeksSinceStart, 1/7)` где `weeksSinceStart = (today - startDate) / (7 * 24 * 60 * 60 * 1000)`
Если прошло меньше дня — показываем как 1 день (≈0.14 недели), чтобы избежать деления на ноль.

**Days since last visit**: `floor((today - lastVisitDate) / (24 * 60 * 60 * 1000))`
С rounding вниз (полные дни). Для today-вчера = "1 день назад".

**Predicted end**: Если `visits.length >= 2` и `frequency > 0`:
`today + (remainingSessions / frequency) * 7` дней.
Округляем до целого числа дней, форматируем как дату.

**Longest gap**: `max(visit[i+1].date - visit[i].date)` по всем парам последовательных визитов.
Результат в днях.

### 3. Форматирование

Русские плюральные формы через существующий `shared/lib/pluralize.ts`:
- "2.3 раза в неделю" (frequency, 1 знак после запятой)
- "5 дней назад" / "1 день назад" (days, через pluralize)
- "~20 июня 2026" (predicted end, через toLocaleDateString('ru-RU'))
- "Макс. перерыв: 9 дней" (longest gap)

### 4. Скроллинг (нет изменений)

Блок статистики статический, под таймлайном. Никакого влияния на скролл или лейаут.

### 5. i18n

Только русский язык (как и весь проект).

## Risks / Trade-offs

- **Прогноз без frequency**: Точность прогноза зависит от количества данных. С 2-3 визитами прогноз может быть неточным — поэтому скрываем при < 2 визитов.
- **Дата в localStorage**: Все вычисления отталкиваются от `new Date()`. Если пользователь не открывал приложение неделю — статистика устареет до следующего визита. Это OK для текущей модели (нет бэкенда).
