## Context

Проект Gym Tracker полностью стилизован через Tailwind CSS v4 с утилитарными классами (113 классов в 6 компонентах). Конвенция проекта (CLAUDE.md) требует БЭМ-методологию и запрещает Tailwind. Решение принято в пользу миграции одним проходом.

**Текущее состояние:**
- `tailwindcss` + `@tailwindcss/vite` как build-time зависимости
- `autoprefixer`, `postcss` как dev-зависимости
- `@import "tailwindcss"` в index.css
- `@apply` для базовых стилей body
- Tailwind-классы инлайн в JSX во всех компонентах

**Ограничения:**
- Сборка через Vite 7
- Деплой на GitHub Pages через `gh-pages`
- PWA через `vite-plugin-pwa` (не должен быть затронут)

## Goals / Non-Goals

**Goals:**
- Полное удаление Tailwind CSS из проекта (зависимости, конфигурация, импорты, классы)
- Внедрение БЭМ-методологии с React-неймингом: `BlockName-ElemName_modName_modValue`
- Использование `@bem-react/classname` для программного конструирования имён классов
- Вынос статических инлайн-стилей в CSS-классы
- Динамические стили через CSS custom properties (прогресс-бар) и ref.setProperty (свайп-анимация)
- Нативные CSS-псевдоклассы (`:disabled`, `:hover`, `:focus-visible`) вместо модификаторов для стандартных состояний
- Дизайн-токены в отдельном файле `src/styles/tokens.css`
- Pixel-perfect миграция — визуальное поведение не должно измениться

**Non-Goals:**
- Изменение визуального дизайна
- Изменение компонентной модели или структуры React-компонентов
- Добавление CSS-препроцессоров (Sass, Less)
- Внедрение CSS Modules (конфликтует с БЭМ)
- Изменение PWA-конфигурации

## Decisions

### 1. CSS файл рядом с компонентом (вариант B)

Каждый компонент получает отдельный `.css` файл в той же директории. Файл импортируется в `main.jsx` один раз (не в компоненте).

**Альтернатива A (один файл):** Отклонено — файл был бы ~400 строк, трудно навигировать.
**Альтернатива C (папка styles/):** Отклонено — CSS файл рядом с JSX удобнее при рефакторинге (перемещаются вместе).

### 2. @bem-react/classname вместо ручной конкатенации

Библиотека гарантирует корректность БЭМ-имён, поддерживает модификаторы, миксы, и фильтрует falsy-значения. React-пресет (по умолчанию) даёт ровно нужный формат: `e: '-'`, `m: '_'`, `v: '_'`.

**Альтернатива (ручная конкатенация):** Отклонено — чревато ошибками, дублированием, отсутствием типобезопасности.

### 3. Нативные псевдоклассы вместо модификаторов

`:disabled`, `:hover`, `:focus-visible` покрывают стандартные состояния. БЭМ-модификаторы остаются только для кастомной логики (меню открыто/закрыто, свайп в процессе).

**Пример:** `<button disabled={remaining === 0}>` + CSS `.Btn:disabled {}` вместо `.Btn_disabled`.

### 4. CSS custom properties для прогресс-бара

Ширина заполнения прогресс-бара — производная данных (`visits / totalSessions`). Значение передаётся через `style={{ '--progress': '75%' }}` и потребляется в CSS: `width: var(--progress)`.

**Альтернатива (useRef + setProperty):** Избыточно для статического рендера, где значение не меняется в реальном времени.

### 5. ref.setProperty для свайп-анимации

Свайп в `SwipeableVisit` требует обновления `translateX` в реальном времени (mousemove/touchmove). CSS-свойство `--swipe-offset` устанавливается через `ref.current.style.setProperty('--swipe-offset', offset)`. Transition-поведение управляется БЭМ-модификаторами: `_dragging` (transition: none), `_snapped` (transition: ease).

**Альтернатива (requestAnimationFrame + инлайн style):** Менее чистое разделение логики и стилей.

### 6. Структура tokens.css

Один файл `src/styles/tokens.css` с CSS custom properties на `:root`. Содержит: цвета, радиусы, тени, переходы, базовые шрифты. Импортируется первым в `main.jsx`, чтобы быть доступным во всех остальных CSS-файлах.

### 7. Удаление App.css

Файл содержит только мёртвый код (шаблон Vite), не используется нигде. Удаляется без замены.

## Risks / Trade-offs

| Риск | Митигация |
|------|-----------|
| Визуальная регрессия — отличие на 1-2px из-за разных единиц измерения | Визуальное сравнение «до/после» на каждом компоненте |
| Увеличение размера CSS (Tailwind tree-shakes, здесь явные селекторы) | Общий объём CSS для 6 компонентов несущественен (<20 KB) |
| `@bem-react/classname` добавляет 1 зависимость | Библиотека весит <1 KB gzipped, zero dependencies |
| Ошибки при конструировании имён элементов | `cn('Block')('Element')` типобезопаснее ручной строки; линтер ESLint проверит импорты |

## Open Questions

Нет — все дизайн-решения приняты в процессе исследования.
